# Power BI Year Range Filter Custom Visual

## Overview

**PowerBI_YearRange_Filter** is a custom Power BI visual that provides a compact year-range selector using two native HTML `<select>` controls.

The intended UI is:

```text
[ 2020 ]  −  [ 2026 ]
```

The left selector is ascending and the right selector is descending.

The visual accepts one field in its `Year` data role, intended to be:

```text
Dim_Date[Year]
```

Changing either selector applies a Power BI Advanced JSON filter to the bound year column:

```text
Year >= StartYear
AND
Year <= EndYear
```

The goal is for this filter to propagate to the other visuals in the report through the normal Power BI filter context.

---

## Original Requirements

1. Accept `Dim_Date[Year]`.
2. Render two dropdowns.
3. Left dropdown: years ascending.
4. Right dropdown: years descending.
5. No title.
6. User can select start and end years.
7. Selection filters other report visuals.
8. Use Power BI's filter API rather than manually manipulating other visuals.
9. Expose visual formatting through the Power BI Format pane.
10. Package as a `.pbiviz` custom visual.
11. Keep the implementation lightweight and realistic for Power BI.
12. Avoid unnecessary libraries and performance-heavy approaches.

## Year Extraction

The visual reads the categorical data from:

```typescript
options.dataViews[0]
```

and:

```typescript
dataView?.categorical?.categories?.[0]
```

The year values must be:

1. converted to numbers;
2. filtered for finite values;
3. deduplicated;
4. sorted ascending.

The established logic is:

```typescript
this.years = Array.from(category.values)
    .map(v => Number(v))
    .filter(v => Number.isFinite(v))
    .filter((v, i, arr) => arr.indexOf(v) === i)
    .sort((a, b) => a - b);
```

### Previous bug

The dropdown years were previously displayed twice because the code first called `populateSelect()` and then manually appended the same options again.

That issue was fixed by removing the second manual option-generation loop.

Do not reintroduce it.

## Default Range

When there is no compatible existing Power BI filter state, the intended default is:

```text
minimum available year → maximum available year
```

Conceptually:

```typescript
this.startYear = this.years.length
    ? this.years[0]
    : null;

this.endYear = this.years.length
    ? this.years[this.years.length - 1]
    : null;
```

If Power BI supplies a compatible existing filter state, that state should take precedence.

## Filter Target

The visual should derive its target from the assigned category's `queryName`.

Typical Power BI query names look like:

```text
Table.Column
```

The established helper is conceptually:

```typescript
private getFilterTarget(
    queryName?: string
): { table: string; column: string } | null {
    if (!queryName) return null;

    const dot = queryName.lastIndexOf(".");

    if (dot <= 0 || dot === queryName.length - 1) {
        return null;
    }

    return {
        table: queryName.substring(0, dot),
        column: queryName.substring(dot + 1)
    };
}
```

This avoids hard-coding `Dim_Date` and `Year`.

## Applying the Filter

The intended Advanced JSON filter is:

```typescript
const filter = {
    $schema: "https://powerbi.com/product/schema#advanced",
    target: this.target,
    logicalOperator: "And",
    conditions: [
        {
            operator: "GreaterThanOrEqual",
            value: start
        },
        {
            operator: "LessThanOrEqual",
            value: end
        }
    ]
};
```

Then:

```typescript
this.host.applyJsonFilter(
    filter,
    "general",
    "filter",
    FilterAction.merge
);
```

This represents:

```text
Year >= start
AND
Year <= end
```

Do not replace this with manual filtering of the HTML controls. The point is to update Power BI's actual filter context.

---

## Does It Filter Other Visuals?

Yes, that is the intended behavior.

For example:

```text
Start = 2022
End   = 2025
```

creates a filter equivalent to:

```text
Dim_Date[Year] >= 2022
AND
Dim_Date[Year] <= 2025
```

Other visuals connected to the same model/filter context should respond.

The custom visual cannot fix an incorrect or missing Power BI relationship. If `Dim_Date` is not properly related to a fact table, other visuals may not respond even though the custom visual correctly applies the filter.

## Restoring Filter State

The visual has logic intended to inspect:

```typescript
options.jsonFilters
```

and recover two conditions:

```text
GreaterThanOrEqual
LessThanOrEqual
```

The values are converted with:

```typescript
Number(condition.value)
```

Both values must be finite before being accepted.

If a compatible filter is not found, the visual falls back to the minimum/maximum available years.

## Performance Expectations

The visual should remain lightweight.

The core workload is only:

```text
read year category
→ deduplicate/sort
→ populate two native selects
→ apply Power BI filter
```

No expensive rendering loop is required.

Do not introduce React, D3, chart libraries, or other frameworks unless a real requirement appears.

---

## Design Expectations

The visual should remain compact enough to function as a report control rather than a chart.

The current concept intentionally has:

- no title;
- two dropdowns;
- a simple separator;
- native select behavior;
- formatting controls for appearance;
- no unnecessary visual decoration.

The visual should work at different Power BI visual container sizes without assuming a fixed report canvas size.
